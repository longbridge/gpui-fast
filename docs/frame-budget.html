The gain tracks how much actually changed

The horizontal axis is the share of cells whose text differs from one frame to the next. The baseline is a flat line: it costs the same whether anything changed or not, because it rebuilt every layout node either way. The current tree follows the real workload — the quieter the interface, the cheaper the frame.

100% is the worst case by construction: every cell's text is different every frame, so there is nothing anywhere to reuse. It is still −16%.

Where the gain comes from

A frame walks the element tree three times: build constructs it and asks for layout, prepaint resolves positions (layout happens here), paint emits the primitives handed to the GPU. These three are timed inside the frame with Instant, so the compositor cannot distort them.

Prepaint falls from 5.96 ms to 0.46 ms — that is −92%. In a still frame, layout costs close to nothing. Paint's 4.7 ms does not move at all: it is the same at 0%, 25% and 100%, because that phase does not care how much changed.

Produced by cargo run -p gpui --example grid_frames --release -- 50 50 <percent>, running the two builds alternately so drift lands on both. Phase timings are taken inside the frame and are independent of the compositor; whole-frame times are the smallest of three runs, because interference only ever makes a frame slower.
