# GPUI Fast v0.1.0

GPUI Fast's first crates.io release brings incremental rendering, cached
scroll composition and native window composition to GPUI. It includes
upstream changes through Zed commit
[`a1b71072e5`](https://github.com/zed-industries/zed/commit/a1b71072e5b43faef437b471e988fbb5f972c99c).

## Performance: reuse work between frames

**Retained Mode** keeps the output of unchanged views instead of rendering,
laying out, prepainting and painting them again. Dependency tracking observes
entities, globals, list and scroll state, hover, pointer position and modifier
keys, so a change rebuilds the views that depend on it. Retained layout nodes
also preserve Taffy's per-node cache across frames.

In the existing Linux release-build benchmarks, a headless window of 60 panels
with 64 labels each takes **0.19 ms instead of 3.31 ms** when no panel changes
(94% less CPU time per frame). Updating one panel takes **0.71 ms instead of
6.72 ms** (89% less); updating all 60 takes **7.38 ms instead of 10.33 ms**
(29% less). Here the baseline is the same build with view retention disabled.

In real-window `gpui_perf` measurements against the upstream `gpui-pre` 0.3.7
snapshot, main-thread CPU time per frame falls by **82–88%** for component
gallery animation and scrolling, and **73–75%** for the trading workspace:

| Workload | Upstream gpui-pre | GPUI Fast |
| --- | --- | --- |
| Spinner animation | 5.91 ms | 0.73 ms (−88%) |
| Sidebar scrolling | 5.95 ms | 0.79 ms (−87%) |
| Data table scrolling | 3.07 ms | 0.54 ms (−82%) |
| Streaming quotes | 5.06 ms | 1.35 ms (−73%) |

These are previously recorded Linux release-build results, at up to 144 fps,
with each real-window figure averaged over two alternating runs. They describe
specific workloads, rather than a fresh comparison against the upstream commit
bundled in v0.1.0. The [README](../../README.md#retained-mode) has the full
results, process CPU measurements and reproduction commands.

**Scroll layers** extend reuse to moving content. Eligible scroll containers
rasterize content into cached GPU tiles, then composite those tiles at the new
scroll offset. `uniform_list` and `list` retain rows separately, updating rows
entering the cached region or affected by hover and content changes. Dirty
tiles outside the viewport wait until they become visible before rasterizing.

Supported renderers are **Metal on macOS, wgpu on Linux and Direct3D 11 on
Windows**. Headless Linux release-build measurements over 300 wheel-scroll
frames, with retained views enabled in both columns:

| Workload | Scroll layers off | Scroll layers on |
| --- | --- | --- |
| Child-view scrolling | 0.619 ms | 0.066 ms (−89%) |
| Same-view scrolling | 0.578 ms | 0.232 ms (−60%) |
| Uniform list scrolling | 0.397 ms | 0.137 ms (−65%) |
| Variable-height list scrolling | 0.377 ms | 0.147 ms (−61%) |

These isolate the benefit of scroll layers and are separate from the
upstream comparison above. Layers fall back to direct drawing when reuse
cannot preserve the output or when estimated rebuilding costs exceed its
budget. Repeatedly expensive updates trigger a cooldown rather than repeatedly
rebuilding the cache. See [Scroll layers](../scroll-layers.md) for details.

Other optimizations reduce text and frame bookkeeping costs: retained text
measurements and recently shaped lines are reused, eligible numeric strings
are assembled from cached glyph layouts, global element IDs are cached, and
scene sorting and retained records require fewer allocations.

## Window composition: native content with GPUI overlays

The release incorporates the window composition work proposed in
[zed#62379](https://github.com/zed-industries/zed/pull/62379), still unmerged
upstream as of v0.1.0. Native views can sit above GPUI's base content while
GPUI popovers, menus, tooltips and dialogs remain above them.

Composition is opt-in through `Window::enable_window_composition`. Its
surface tree manages native views, external GPU producers and additional
GPUI surfaces, including ordering, nesting and reparenting.
`Window::with_composition_surface` routes GPUI painting to a chosen surface.
Retained views preserve their surface switches when replayed, and composition
inside scroll layers follows the scrolled content.

Platform integration uses AppKit views and Metal layers on macOS,
DirectComposition on Windows, Wayland subsurfaces and X11 child windows on
Linux. Try the integration example from a v0.1.0 checkout:

```sh
cargo run -p gpui_perf --example native_webview
```

It embeds **WKWebView on macOS** and **WebView2 on Windows**, showing overlays,
resizing and focus/input handoff. On **Linux**, an independent wgpu device
draws into the native surface to demonstrate the composition contract; the
example does not embed a Linux WebView. X11's rectangular SHAPE cutouts limit
overlay shadows and rounded corners over native content.

## Upstream: synchronized with Zed's GPUI

v0.1.0 is synchronized through
[`a1b71072e5b43faef437b471e988fbb5f972c99c`](https://github.com/zed-industries/zed/commit/a1b71072e5b43faef437b471e988fbb5f972c99c),
the latest upstream revision imported for this release. The final sync
replays 13 relevant Zed commits across 26 tracked directories, preserving
their vendor history. It includes upstream's incremental `GlobalElementId`
hashing, shared Apple renderer and Linux display-connection changes, with
the retained-rendering and composition hooks adapted to them.

GPUI Fast's implementation stays in `fast/` modules; upstream files contain
small hooks. Existing GPUI application APIs are preserved, with the renderer
and composition additions documented in
[Upstream sync](../upstream-sync.md#where-our-api-differs-from-upstreams).
[UPSTREAM](../../UPSTREAM) records the source and import commits.

## Use v0.1.0

The release publishes nine crates: `gpui-fast`, `gpui-fast-macros`,
`gpui-fast-apple`, `gpui-fast-wgpu`, `gpui-fast-macos`, `gpui-fast-linux`,
`gpui-fast-windows`, `gpui-fast-web` and `gpui-fast-platform`.
Alias dependencies to GPUI's original library names:

```toml
[dependencies]
gpui = { package = "gpui-fast", version = "0.1.0" }
gpui_platform = { package = "gpui-fast-platform", version = "0.1.0", features = ["wayland", "x11"] }
```

The features above select Linux backends; omit them on macOS and Windows.
GPUI Kit applications need to select the same core through the
[gpui-pre compatibility crates](../../compat/README.md), which target the
0.3.8 snapshot. Adding `gpui-fast` alone does not replace GPUI Kit's dependency.
The Web backend is packaged, but the scroll-layer and native-composition
platform support described above applies to desktop backends.

The project remains experimental. State read outside tracked entities,
globals or list/scroll state needs `cx.notify()` when it changes.
`GPUI_VIEW_RETENTION=0` and `GPUI_SCROLL_LAYERS=0` disable the respective
optimizations for comparison or debugging. Randomized frame and input
comparisons, plus renderer pixel tests, check retained and composited output
against direct drawing; see [Retained mode](../retained-mode.md#verification).
